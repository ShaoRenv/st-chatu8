# 变量系统 使用说明

给生图 LLM 用的一套 tag 存储：多个角色、每个角色多套服装、当前形象与状态，靠引用调用。

## 一、装好之后要做的三件事

1. **开开关**：设置 → 主设置页 → 「变量系统（tag 存储）」（默认已开）。
2. **挂提示词**：把 `prompts/` 下三份文本挂到生图 LLM 能看到的地方（世界书常驻条目 / 预设里的固定段落）：
   - `变量更新规则.txt` —— 告诉模型每个字段什么时候该改
   - `变量输出格式.txt` —— 告诉模型输出格式
   - `变量结构.txt` —— 结构说明（当前值由插件自动注入，不用手填）
3. 正常生图。模型在提示词末尾多输出一段 `<变量更新>…</变量更新>`，插件自动摘掉并写进这一楼。

## 二、数据结构

```json
{
  "角色列表": {
    "爱莉希雅": {
      "key": "爱莉希雅,Elysia",
      "人物形象": "1.5::elysia (honkai impact 3rd)::,pink long hair,purple eyes",
      "服装列表": {
        "白色睡衣": "white nightgown,lace trim",
        "比基尼": "white bikini top,gold chain"
      },
      "人物状态": "$角色列表/爱莉希雅/服装列表/比基尼$,-gold chain,$角色列表/爱莉希雅/人物形象$,cumdrip,after sex"
    }
  }
}
```

| 字段 | 作用 |
|---|---|
| `key` | 关键词触发，逗号分隔；正文里出现任一词这个角色才参与生图。不写＝常开 |
| `人物形象` | 角色固定形象 tag（建议带同人 tag + 权重，如 `1.5::hutao (genshin impact)::`） |
| `服装列表` | 多套服装，一套只存一次 |
| `人物状态` | **当前画面的组装串**：引用 + 临时 tag。它驻留，直到被改写或淡化 |

## 三、引用语法（写在值里）

```
$爱莉希雅$                              整个角色的投影（形象 + 状态）
$角色列表/爱莉希雅/人物状态$             取某个字段
$角色列表/爱莉希雅/服装列表/比基尼$      取某套服装
$服装列表/比基尼$                       相对引用（写在角色内部的值里）
$/角色列表/爱莉希雅/人物形象$            / 开头＝从根算
```

- **不带 `$` 的字符串永远是字面 tag**，不会被当成引用。
- 找不到的路径**原样保留**，不会误删你的东西。
- **对象（`服装列表` 这类）不会自动进图**，只有被引用才展开。

### 多重调用（省字写法）

同一个 `$...$` 里可以用逗号分开写多项；**第 2 项起接着第 1 项所在的位置继续写**，写不中再按第 1 项的规则找。

```
$沈慕微/人物状态,服装列表/冷清首座蓝白渐变长袍$        = $沈慕微/人物状态$,$沈慕微/服装列表/冷清首座蓝白渐变长袍$
$沈慕微/人物状态,-服装列表/冷清首座蓝白渐变长袍$,nude  = 旧写法 -$角色列表/沈慕微/服装列表/冷清首座蓝白渐变长袍$
```

花括号 = 并列候选，等于把每一项分别写一遍（任意层可用、可嵌套）：

```
$角色列表/{沈慕微,江念}/人物状态$                      = $角色列表/沈慕微/人物状态$,$角色列表/江念/人物状态$
$沈慕微/{人物形象,服装列表/日常}$
```

- 项以 `/` 开头 = 从根算；项以 `-` 开头 = 把这一项展开出的 tag 从这次调用里减掉（不是有效路径就当字面 tag 减，如 `-smile`）。
- 花括号不能紧跟在 `$` 后面（那是 `${JSON}$` 预设调用），前面要先有共同前缀。
- 查不到的项原样保留；整组都查不到 = 整组原样保留。同一内容被两项引用到时会重复，属正常。
- 两种写法完全等价：拿不准就写全路径。
### 移除语法

```
$角色列表/爱莉希雅/服装列表/比基尼$,$角色列表/爱莉希雅/人物形象$,-gold chain
```

`-tag` 对**本值里的所有引用**生效，与位置无关；只减引用结果，不动你自己写的字面 tag。

## 四、调用扩展的角色预设（可选）

```
${"name":"xiao hong","angle":"from front"}$                        只有角色特征
${"name":"xiao hong","angle":"from front","upperBody":"facial"}$   特征＋头部（不加上半身）
${"name":"xiao hong","angle":"from front","upperBody":"sfw"}$      特征＋头部＋上半身(穿)
  …再追加 "lowerBody":"sfw" / "nsfw"                             再加下半身
```

- **必须带 `angle`**，否则会被当成服装调用。
- 不写 `upperBody` ＝ 只有特征，不会带出头部。
- `upperBody` 写 `facial`（任何非 sfw/nsfw/hidden 的值）＝ 只加头部。
- 旧格式 `$xiao hong-from front-sfw-upperBody$` 也支持，但没有「只有头部」的写法。

## 五、更新格式（模型输出）

```
<变量更新>
{ "角色列表": { "爱莉希雅": { "人物状态": "$角色列表/爱莉希雅/服装列表/校服$" } } }
</变量更新>
```

- 只写变化的部分；**空字符串 = 删除该字段**；对象 = 往库里加条目。
- 这段会被插件从提示词里摘掉，不会进图片提示词，也不会显示在聊天里。
- 坏 JSON：整段丢弃、不写变量，但照样摘掉（保证画面不被污染）。

## 六、存在哪

写在**消息楼层变量**里，命名空间 `st-chatu8`：`chat[i].variables[swipe_id]["st-chatu8"]`。

- 跟聊天文件走；删楼 / swipe 自动隔离；不会碰 MVU 的 `stat_data`。
- 读取时从当前楼层往前找第一个有该命名空间的楼层。

## 七、排错

- F12 控制台输入 `window.stChatu8Vars` 应有对象；`window.stChatu8Vars.tags()` 看当前存储。
- 调试面板：`window.stChatu8VarsDebug.show()`（面板里可读取/指定 JSON 写入楼层变量、看解析预览；`info()` 看版本与钩子统计）。
- 插件日志前缀 `[ChatU8 vars]`；`ChatU8: 变量块已解析并写回楼层 N` 表示写入成功。
- 设置里关掉「变量系统」开关即完全停用（`render` 不再替换、更新块不再解析）。
